The participant view (`/participant`) gains audio: recording in the composer and an audio player with the machine transcription under it. Both are opt-in or additive. Outside `/participant` the markup and behavior do not change: the operator's `AudioRecorderButton` only re-exports its format constants, which moved to `audioRecorderFormat.ts`, and the stylesheet gains `.cv-p-*` rules only.

- **Optional `audioRecording` prop** on `ConversationThread` and `ParticipantConversations` (type `ParticipantAudioRecordingOptions`). Without it the microphone is not drawn. With it, the microphone takes the place of the send button only while the draft is empty, and sending the recording goes through the same attachment path as any file, so the text draft and the attached files are left untouched. The channel can only switch the microphone off: the `portal` and `webchat` channels never record. `maxDurationMs` and `maxSizeBytes` can only lower the defaults (5 minutes, 16 MiB, and the channel's ceiling). `onCaptureChange(isCapturing)` reports when the microphone is in use, so the host can register the capture in progress. Recording states: idle, requesting, recording, review, denied, unsupported, empty, too large. An interruption while recording (hidden tab, page hide, microphone track ended or muted for more than 3 seconds) stops the take and moves to review; in review it pauses and keeps the take. Unmounting the component discards it. The microphone is released on every exit.
- **Audio attachments** show the new player and, when the server sends one, the transcription block: pending (a "Transcribing…" line), ready (a notice that the text was generated by machine, the text with show all / show less, or "Nothing was said in the audio" when empty), and too long (a notice with the applied limit). `failed` without a reason, `disabled` and missing transcription show only the player.
- **Default markup and style change (participant view only)**:
  1. The native `<audio controls>` is replaced by the `.cv-p-audio` player: play and pause, position, playback speed.
  2. `preload="none"` is kept, without native controls. The URL is resolved on mount by attachment id and assigned to `src`; nothing is downloaded before the first tap, and the duration appears after that tap when the server does not send `durationMs`.
  3. The file name is drawn after the player.
  4. The `cv-p-attachment__audio` class is no longer rendered. Its CSS rule stays in the stylesheet until the next major.
  5. Starting one audio pauses the one that was playing before, any participant-view player on the page. The operator's player and a second copy of the package are not coordinated.
  6. New labels, optional, with English defaults (see below).
- **New optional labels** in `ParticipantConversationsLabels`: `recordAudio`, `recordingInProgress`, `stopRecording`, `recordingElapsed`, `reviewAudio`, `sendAudio`, `discardAudio`, `microphoneDenied`, `recordingUnsupported`, `audioEmpty`, `audioTooLarge`, `audioPlayer`, `playAudio`, `pauseAudio`, `audioPosition`, `audioPositionValue`, `playbackRate`, `audioUnavailable`, `transcribing`, `transcriptionReady`, `machineTranscription`, `emptyTranscription`, `transcriptionTooLong`, `showFullTranscription`, `collapseTranscription`. Defaults are exported as `DEFAULT_PARTICIPANT_AUDIO_LABELS`. A host that does not translate them shows English. The same defaults are also part of `DEFAULT_PARTICIPANT_CONVERSATIONS_LABELS`. `{minutes}` in `transcriptionTooLong` is computed by the UI from `maxDurationMs` (floor to whole minutes; below one minute nothing is drawn); the server does not send it.
- **WhatsApp**: do not turn the microphone on with `channel="whatsapp"` before validating it end to end. The recorder produces WebM/Opus on Chromium, which WhatsApp does not accept.
- **Unchanged without the prop and without audio**: the composer and the message bubble keep the same markup, byte for byte. This is pinned by the golden fixtures `thread-empty-draft` (empty composer, no prop) and the nine existing `*.golden.html` files.
- **Dependency**: `@adatechnology/conversation-contracts` goes to minor in the same release. It adds the optional `durationMs` and `transcription` fields to participant attachments. Unknown keys are stripped, but an invalid `transcription` or `durationMs` (unknown status, non-string `text`) fails that attachment's schema. Hosts should validate per attachment (`participantTranscriptionSchema.safeParse`) and drop the field when it fails.
